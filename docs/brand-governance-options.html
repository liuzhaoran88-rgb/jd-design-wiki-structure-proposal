STRUCTURE OPTIMIZATION

基于品牌和多端多 APP 场景的结构优化方案

用“共享权威源 + 场景投影 + Profile 继承”的方式，让设计知识既能统一管理，也能被 AI 按场景精准调用。

上半部分解决品牌规范怎么管；下半部分解决主 APP、子 APP、小程序、PC 端如何共享基础知识，并保留各自差异。

品牌方案：品牌中台 + 场景投影

品牌定义集中维护，APP 页面、大促、子品牌只写应用规则、覆盖规则和例外规则，避免同一套品牌规范在多处重复和漂移。

核心逻辑

1

品牌中台是唯一权威源

集团品牌、C 端品牌、子品牌继承、APP 品牌资产，都先回到一个中心目录管理。

brand taxonomy brand tokens logo / color voice / image
2

场景投影只写应用规则

APP 页面、大促活动、业务线页面不重新定义品牌，只描述本场景如何使用、覆盖或限制。

page brand-usage campaign overlay app version exceptions
3

AI 通过索引自动组装

AI 根据平台、人群、页面、子品牌、活动、APP 版本，选择需要加载的品牌规则包。

brand-index.yaml ai-schema.yaml rule selector review checklist

维护边界

品牌定义改动 回到 foundations/brand，例如京东红、Logo、Joy、品牌语气、子品牌继承关系。
页面使用差异 写在页面自己的 brand-usage.md，例如首页可以强品牌，结算页要克制。
大促临时覆盖 写在 brand-overlay.md，例如 618 允许更高氛围，但不能覆盖主流程效率。
APP 大改版 APP 品牌规则版本化，避免 v16、v17 的 UI 品牌策略互相污染。

典型场景

生成京东 APP 618 首页 集团品牌 + C 端品牌 + APP v16 + 首页 brand-usage + 618 brand-overlay。
生成日常频道页 集团品牌 + C 端品牌 + APP 当前版本 + 频道页 brand-usage，保持京东识别但不过度营销化。
APP 大改版页面适配 集团品牌 + C 端品牌 + APP v17 改版规则 + 页面 brand-usage，检查旧页面是否符合新视觉语言。
检查购物车 / 结算页 集团品牌 + C 端品牌 + APP 当前版本 + 主流程页面规则，重点检查红色使用、Joy 出现边界和转化效率。

多端多 APP 方案：共享核心 + 端 / APP Profile

主 APP、子 APP、小程序、PC 端共同继承设计哲学、品牌核心和基础规范；各端通过 Profile 声明自己的平台约束、版本策略、页面规则和例外。

怎么接入现有框架

核心原则

共享内容不复制 设计哲学、品牌核心、基础 token、通用组件原则，放在共享层统一维护。
每个端 / APP 建 Profile 主 APP、子 APP、小程序、PC 端只声明继承了什么、覆盖了什么、有哪些例外。
页面规则继续场景化 首页、搜索、PDP、购物车、频道页、大促页，仍然写自己的 page-usage / brand-usage。

共享核心

设计哲学、C 端品牌、基础 token、通用原则。

→

端 / APP Profile

主 APP、子 APP、小程序、PC 端的继承、覆盖、例外和版本。

→

页面场景

首页、频道页、PDP、购物车、大促页的具体应用规则。

app_profile:
  id: jd-main-app
  inherits:
    - knowledge/philosophy
    - foundations/brand/consumer
    - foundations/tokens
  platform:
    - ios
    - android
  overrides:
    - app_brand_version: v17
    - navigation_pattern: bottom_tab
    - page_density: high
  owns:
    - page_rules
    - app_specific_components
    - version_changelog

AI 调用顺序

主 APP 大改版首页 共享设计哲学 + C 端品牌核心 + Mobile APP 平台规则 + 主 APP v17 Profile + 首页规则。
小程序频道页 共享设计哲学 + C 端品牌核心 + 小程序平台约束 + 小程序 Profile + 频道页规则。
PC 首页运营区 共享设计哲学 + C 端品牌核心 + PC Web 平台规则 + PC Profile + 首页运营区规则。

最终判断

这套结构的核心价值：品牌有统一权威源，多端多 APP 有清晰继承关系，页面和活动场景也能被 AI 精准调用。
